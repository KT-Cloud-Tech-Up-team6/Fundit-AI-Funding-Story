### 병목 확인·한계

| 관측 | 해석 |
|---|---|
| 이미지 단계 857.720초 중 API 호출 활성 구간 약 123.344초 | 호출 구간의 합집합; 병렬 호출 시간의 단순 합이 아님 |
| 나머지 약 734.376초 | 공유 쿨다운·페이싱·스케줄러 구간. 전부 불가피한 공급자 대기라고 단정하지 않으며 완료 시간에서 제외하지 않음 |
| 전체 179.508초 단축, 이미지 429 9→25회 | 대기 정책의 절충. 이번 단일 실행으로 429 감소·안정성 개선을 입증하지 못함 |
| 별도 진단: 단일 호출 5.441초 성공; 이후 5.185초·5.507초 성공 뒤 429 | 전체 실측 종료 후 수행한 4개 진단 호출(3 성공·1 실패); 위 성능 표본에 합산하지 않음 |
| 429 응답 | `Resource has been exhausted (e.g. check quota).` — 구체 metric·reason·Retry-After·RetryInfo 없음 |
| 할당량 조회 | 조회 가능한 콘솔·API 정보로 해당 응답의 정확한 제한 수치를 확정하지 못함; 무제한이라는 뜻이 아님 |
| 남은 조건 | 공급자 측 실제 허용 처리량·용량 제한 확인 후 정책 재측정. 현재 결과로 5분 달성 완료를 선언하지 않음 |

활성/대기 구간은 반올림된 이벤트 시각에서 사후 계산한 근삿값이다. 최초 실행의 오류 분류기는 일반적인 `check quota` 안내도 quota로 분류했으므로 원시 분류값을 고정 할당량 초과의 근거로 사용하지 않는다. 후속 분류기는 구체적인 초과 근거가 없으면 `resource_exhausted`로 남긴다. 공개용 수치 JSONL에서는 이 미확정 분류값을 제외했다.

Google 공식 근거: [429 대응 — global·지수 백오프·트래픽 평탄화](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/deploy/error-code-429), [재시도·jitter·페이싱 설명](https://cloud.google.com/blog/products/ai-machine-learning/reduce-429-errors-on-vertex-ai).

## 재현

Google ADC와 모델 설정·Pretendard·Chromium이 준비된 환경에서 실행한다.
`--output`에는 기존 파일과 겹치지 않는 경로를 사용한다.

```bash
PYTHONPATH=src python scripts/benchmark_generation_runtime.py --runs 3 --output docs/evidence/runtime-standard.jsonl
PYTHONPATH=src python scripts/benchmark_generation_runtime.py --runs 1 --strengths 12 --output docs/evidence/runtime-largest.jsonl
```

생성량 상한 구성은 강점 12개를 각각 2개 이미지 블록으로 배치한 합성 부하 입력이다.
생성 이미지 개수의 상한이며, 참조 이미지 수·입력 크기·동시 요청까지 최대화한 부하 시험은 아니다.
