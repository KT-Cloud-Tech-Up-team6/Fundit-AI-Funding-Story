# Funding Story 상세페이지 초안 품질 개선 계획

| 범위 | 결정 | 검증 |
|---|---|---|
| 리워드 카드 | 원본 템플릿을 `price` 하나의 고정 디자인으로 둔다. 정가·할인가 노드 없이 `가격`만 표시한다. 브랜드 톤 구분선은 이미지 세로 중앙에 두고 제품명·구분선·가격 글자 영역 간격을 맞춘다. 제품명은 구분선과 같은 폭의 영역에서, 가격 글자는 배경 안에서 각각 가로 중앙 정렬한다. 미등록 선물 카드는 유지한다. | 1·2·3개 리워드 조립 결과와 PNG 색상·정렬 확인 |
| 제품별 블록 | 청소기 전용 문구·이미지 설명을 생성 입력에서 제거한다. 강점별로 다양한 중립 레이아웃을 선택하고 사용자 사실을 원고·이미지 지시문의 기준으로 삼는다. | 가전·비가전 입력의 템플릿/프롬프트에 타 제품 표현이 없는지 확인 |
| 원고 | 사용자 정보를 그대로 복제하지 않아도 된다. 사실에 근거한 세분화·확장은 허용하되 없는 성능·인증·가격·비교 우위는 만들지 않는다. | 기존 원고 제약과 슬롯 검증 유지 |
| 하단 본문 | `프로젝트 예산` → `프로젝트 일정` → `프로젝트 팀 소개` → `신뢰와 안전`. 상위 제목 왼쪽 짧은 세로선과 섹션 사이 구분선, 안전 하위의 `크라우드 펀딩에 대한 안내` → `프로젝트 정책` → `예상되는 어려움`을 표현한다. | HTML 구조·escape·브라우저 배치 확인 |
| 고정 안내 | 모든 프로젝트에 동일한 Fundit 중립 안내를 코드에서 제공한다. 텀블벅의 법률·환불 문구는 복사하지 않는다. | 채팅 입력이나 LLM 결과가 고정 문구를 바꾸지 못하는지 확인 |
| 향후 확장 | 사용자가 하단 텍스트에 별도 내용을 요청하는 기능은 **이번 범위에서 제외**한다. 향후 도입 시 기존 섹션 뒤 최하단에 배치한다. 리워드 상세와 무관하다. | 현재 요청/결과 DTO에 새 필드가 없는지 확인 |

## 순서·계약

1. AI의 리워드 원본 템플릿과 제품 중립 프롬프트/템플릿을 수정한다. 리워드의 조건부 디자인 변형은 도입하지 않는다.
2. AI의 하단 HTML을 계층화하고 브라우저에서 확인한다.
3. 테스트·문서를 갱신한다. 기존 실측 PNG/HTML은 과거 기록으로 보존한다.
4. 기존 `TEXT` HTML의 `p`·`strong`·`br` 계약으로는 시각 계층을 표현할 수 없다. AI는 `section`·`h2`·`h3`·`hr`와 코드 소유 정적 스타일을 사용한다. BE의 저장/정제와 FE의 표시/편집 경계에서 해당 마크업·스타일의 왕복 보존을 확인·반영해야 한다. `IMAGE/TEXT` 블록 DTO는 유지한다.

고정 안내는 법률·환불·서비스 약관의 확정 문구가 아니다. 운영 반영 전 서비스 정책 담당자의 문구 확인이 필요하다.
